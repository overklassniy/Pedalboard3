Pedalboard3 Documentation

A free, open-source VST3 and LADSPA plugin host for live performance, built on JUCE 8 and C++20. Pedalboard3 is a modernized rebuild of the original Pedalboard2 that preserves the familiar UI while running on modern audio frameworks.

Getting Started

Assuming this is the first time you have used the app, there are a few things you will want to set up before you can get the most out of it:

  • Audio Settings
  • Plugin List and Scanning
  • Your First Patch
  • A Basic MIDI Mapping
  • Switching Between Patches

Audio Settings

To start off, check that your audio settings are configured the way you want. Open the Audio Settings dialog from the Options menu. See the Audio Settings section below for the full list of options.

Because Pedalboard3 is intended for realtime use, a buffer size no larger than 256 samples is recommended (about 10 ms total latency). On Windows, ASIO drivers generally offer the best low-latency performance. On Linux, ALSA or JACK backends are available. On macOS, CoreAudio is used.

Plugin List and Scanning

Next, tell the app where to find your plugins. Open the Plugin List dialog from the Options menu. You will see a list of all available plugins on your system, including Pedalboard3's built-in processors.

To add your own plugins, click the Options... button and select Scan for new or Updated VST plugins.... This opens a window where you can add and remove plugin directories with the + and - buttons. Clicking Scan loads each plugin found in the selected directories, one after another, to verify they are valid. Once the scan is complete, your plugins appear in the Available Plugins list.

Plugin scanning runs in a separate out-of-process scanner (Pedalboard3Scanner.exe) with crash isolation. If a plugin crashes during scanning, it is automatically added to the plugin blacklist and skipped on future scans, so a single bad plugin cannot take down the host.

Your First Patch

All Pedalboard patches start with an audio input node, an audio output node, and an empty canvas between them. To add a plugin, double-click in the main plugin field. A popup menu lists the available plugins. Click the one you want to add it to the patch.

All plugins are represented the same way: input ports on the left of the node, output ports on the right. The buttons along the bottom of each node are:

  • Edit — opens the plugin's editor window.
  • Mappings — opens the plugin's mappings window.
  • Delete (x) — removes the plugin from the patch.

To connect the plugin to your soundcard's input, drag from the relevant port on the Audio Input node to your desired port on the plugin. To delete a connection, click it to select it, then press the Delete or Backspace key.

A Basic MIDI Mapping

One of the key features of Pedalboard3 is mapping plugin parameters to physical MIDI controllers. Drag a connection from the Midi Input node to the plugin's parameter input. By default this opens the plugin's Mappings window automatically.

In the Mappings window, click add MIDI to create a new mapping. The left combo box selects the MIDI CC, and the right combo box selects the parameter it will be mapped to. Play with your MIDI controller and the plugin's parameter will change accordingly. See the MIDI Mapping section for the other controls.

Switching Between Patches

Pedalboard3 is designed to make it easy to set up multiple patches and quickly switch between them. The main patch controls are at the bottom left of the main screen. To add a new patch, click the combo box's drop down button and select <new patch>. Switch between patches via the combo box or the +/- buttons to its right. Patch switching can also be mapped to MIDI CCs or OSC messages; see Application Mappings.

The Canvas

The main canvas (PluginField) shows the plugin nodes and the audio cables connecting them. Each plugin is a PluginComponent with a bypass button, a preset bar, and an editor window.

  • Audio connections are drawn in the audio connection colour.
  • Parameter connections are drawn in the parameter connection colour.
  • Each node has an Edit button to open the plugin editor, a Mappings button to open the mappings dialog, and a Delete (x) button to remove it from the patch.
  • The bypass button silences the plugin without removing it from the signal chain.
  • To delete a connection, click it to select it, then press Delete or Backspace.

Patches and Pedalboard Files

A Pedalboard3 document is a multi-patch .pdl file. Each patch is a complete plugin signal chain (a FilterGraph). Individual graph saves use the .filtergraph extension.

Patch Selection

Switching between patches is done with the patch controls at the bottom left of the main window:

  • The -/+ buttons iterate through the available patches one by one.
  • The Patches: combo box lets you select from a list of all available patches. The combo box text is editable; to rename the current patch, click its text in the combo box.
  • To add a new patch, select <new patch> from the end of the combo box list.

Patch Organiser

For more control over patch organisation, open the Patch Organiser from the Edit menu (Organise patches). The Patch Organiser window lists the patches in the current document with buttons to add, copy, remove, reorder, and import patches from other .pdl files. To rename a patch, double-click its entry in the list.

Plugin Pool and Near-Instant Switching

Patch switching is designed to be near-instant via the PluginPoolManager, which preloads plugin instances for the current patch plus N patches ahead or behind. This avoids the latency of loading plugins from disk at the moment of switching.

Plugins

Pedalboard3 hosts VST3 and LADSPA plugins. The available plugins are listed in the Plugin List dialog (Options menu).

Scanning

To populate the plugin list, click Options... in the Plugin List dialog and select Scan for new or Updated VST plugins.... Add the directories containing your plugins, then click Scan. Each plugin is loaded in turn to verify it is valid.

Scanning is performed by a separate out-of-process scanner (Pedalboard3Scanner) so that a crashing plugin cannot take down the main application. If a plugin crashes during scanning, it is automatically added to the plugin blacklist.

Blacklist

The plugin blacklist skips known-bad plugins during scanning. It is auto-populated when the scanner crashes on a plugin. Manage it through the Blacklist Window, where you can review and remove entries if a plugin has been fixed or updated.

Plugin Presets

Per-plugin presets use the .fxp format.

  • The Preset Bar above each plugin editor shows factory and user-saved presets with import and save buttons.
  • The User Preset Window (Options menu) is the full preset manager: a tree view of plugin directories and their .fxp presets with buttons to copy, remove, import, export, and rename. User presets are stored under <user data>/Pedalboard3/presets/<plugin name>/.

MIDI Mapping

MIDI CC messages can drive plugin parameters and application commands.

  • Open the Mappings Dialog from a plugin node to view and edit the MIDI and OSC mappings for that single plugin. Each MIDI row has a CC combo, a latch toggle, a parameter combo, and a MappingSlider for the bound range.
  • Use MIDI Learn to capture the next received CC for a mapping.
  • The latch toggle controls whether the mapping holds its value or returns to a default when the controller is released.
  • The MappingSlider defines the range of the parameter that the MIDI CC drives.
  • MidiInterceptor is a no-audio plugin that intercepts MIDI messages in the graph and forwards them to the MidiMappingManager.

OSC Mapping

OSC messages can drive plugin parameters and application commands over the network.

  • Configure the OSC port and multicast address in the Preferences dialog.
  • OscInput appears on the canvas as a visual placeholder so you can see which plugins have OSC mappings; actual reception is handled by a juce::OSCReceiver in the main panel.
  • OSC mappings bind an OSC address to a plugin parameter (OscMapping) or to an application command (OscAppMapping). Float and MIDI arguments are dispatched to the registered mappings.

OSC Primer

OSC (Open Sound Control) is a network protocol for sending messages between computers and multimedia devices. It uses UDP and addresses messages to URL-like paths (for example, /pedalboard/patch/next). Arguments can be floats, integers, strings, or MIDI messages. To use OSC with Pedalboard3, configure the receiving port in Preferences, then send OSC messages from your controller software to the computer running Pedalboard3.

Application Mappings

The Application Mappings Editor (Options menu) edits application-level key, MIDI, and OSC mappings via a tree view of command categories. This lets you bind physical controllers to application commands such as patch switching, transport play/stop, and tap tempo, independent of any single plugin.

Tap Tempo

Tap tempo is shared between the MIDI and OSC mapping systems. The Tap Tempo Box calculates the tempo from repeated taps and sends the result to the canvas. TapTempoHelper averages the intervals between the last four taps and returns BPM, resetting below 30 BPM.

Built-in Processors

Pedalboard3 ships with built-in processors in addition to hosted VST3 and LADSPA plugins. Each processor has an on-canvas control component and, where applicable, a full editor window opened from the plugin node.

Level

Volume control. Adjusts the gain of the audio passing through it.

File Player

Plays an audio file from disk, with a waveform display and transport controls (play, loop, return-to-zero, sync).

Output Toggle

Toggles between two output destinations. Useful for routing audio to different outputs during a performance.

VU Meter

Shows the level of the passing audio. A monitoring tool with no effect on the signal.

Audio Recorder

Writes the incoming audio to disk. Provides record and sync controls.

Metronome

Generates click samples in sync with the playhead tempo. Provides play, sync, and measure controls.

Looper

Records input to disk and memory and plays it back. Provides autoplay, bar length, input level, loop level, and stop-after-bar controls.

Safety Limiter and Crossfade Mixer

These are DSP safety modules. The Safety Limiter prevents signal spikes from reaching damaging levels. The Crossfade Mixer provides smooth transitions between signals.

Colour Schemes

The application uses a custom LookAndFeel (BranchesLAF) fed by a named-colour palette (ColourScheme). The default scheme is a warm light beige palette.

  • Open the Colour Scheme Editor (Options menu) to choose, save, and delete .colourscheme presets. The editor has a colour selector, a colour list, and a combo box plus buttons for managing presets.
  • Colour scheme presets are stored as .colourscheme files in the application data folder and loaded at startup.

Audio Settings

The Audio Settings dialog (Options menu) configures the audio interface used by Pedalboard3:

  • Audio device type — selects the audio backend. On Windows the available types are WASAPI (shared), WASAPI (exclusive), WASAPI (shared low latency), DirectSound, and ASIO. On Linux the available types are ALSA and JACK. On macOS the available type is CoreAudio.
  • Output / Input device — selects the physical audio interface. The Test button plays a short test tone through the selected output device.
  • Sample rate / Buffer size — advanced settings shown when the "Show advanced settings..." button is toggled.
  • Control Panel — opens the selected device's own control panel. This button only appears for devices that provide a control panel (e.g. ASIO devices). It is hidden for WASAPI and DirectSound.
  • Reset Device — restarts the audio device, sometimes needed after changing properties in the device's custom control panel.

Audio settings are saved to the application properties and restored on the next launch. When the "save audio settings in .pdl files" preference is enabled, the audio device state is also embedded in the .pdl document.

Preferences

The Preferences dialog (Options menu) configures:

  • OSC port and multicast address
  • Visible I/O nodes (audio, MIDI, OSC)
  • MIDI options (program change, MMC transport)
  • Window options (auto mappings window, loop patches, windows on top, ignore pin names, tray icon, start in tray, fixed-size windows)
  • Whether to save audio settings in .pdl files

Preferences are read and written through the PropertiesSingleton (JUCE PropertiesFile).

System Tray

On Windows and Linux, TrayIcon provides a system tray icon with a right-click popup menu and double-click window toggle. The tray icon is not built on macOS.

Log Display

The Log Display is a component with a read-only text editor, start/stop logging button, and event-type filter toggles. It displays events from the LogFile singleton, which is useful for diagnosing audio, MIDI, OSC, and plugin issues during a session.

Stability Features

Several stability features protect the host during live use:

  • Crash protection wraps risky operations (notably plugin scanning) with SEH on Windows and a worker-thread timeout, with an auto-save callback hook and a watchdog thread for UI hangs.
  • Plugin blacklist skips known-bad plugins during scanning and is auto-populated when the scanner crashes on a plugin. Manage it through the Blacklist Window.
  • Undo/redo actions for filter graph editing (add/remove plugin, add/remove connection) are defined and designed for a juce::UndoManager.
